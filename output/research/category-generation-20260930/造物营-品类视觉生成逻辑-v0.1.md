# 造物营：品类视觉生成逻辑 v0.1

研究日期：2026-09-30  
状态：小样本研究与待验证的产品规则；尚未接入应用，也未完成效果实验。

## 1. 这次研究的范围

目标是让“上传一个商品，得到三套有明显设计差异的样稿”能够扩展到不同品类。用户选择的金典“清晨餐桌”样稿是风格质量参考，不是所有商品的固定模板。

淘宝直接访问被当前浏览器的站点安全策略拦截，本轮没有进入淘宝店铺，也没有完成淘宝站内抽样。替代研究使用独立的品牌官方公开页面：伊利、索尼、优衣库台湾站、宜家中国站；实际查看了其中 10 个画面或模块，另参考了用户提供的金典海报。10 个画面不是 10 个独立商家或 10 个独立商品。

本轮具体覆盖乳品、头戴耳机、T恤、扶手椅。它们只能支持首版设计假设，不能代表所有食品、数码、服装和家居。优衣库台湾站用于观察设计表达，不代表淘宝渠道规范。页面按本次访问状态记录，不作为 2024—2025 年项目经历的证据。

这份研究区分三种内容：

- **观察**：实际看到的官方画面与页面内容。
- **推导**：为造物营提出的设计选择规则。
- **待验证**：是否能由当前模型稳定生成、是否被用户采用、是否提升商业效果。

## 3. 核心生成逻辑

**输入素材 → 识别商品和素材条件 → 选择设计目标 → 规划三套方案 → 分层生成与合成 → 检查并反馈。**

提示词只是执行某一套方案的工具。需要变化的是场景、构图、光线、信息层级和排版，而不只是增加“高级感、有设计感”等形容词。

### 3.1 先建立商品事实卡

| 信息 | 如何得到 | 缺失时怎么处理 |
| --- | --- | --- |
| 商品大类、子类 | 图像识别得到候选，必要时用户纠正 | 不能可靠识别时只问一个关键问题 |
| 外形、可见颜色、原图角度 | 图像观察 | 标为观察结果；不据此猜隐藏结构 |
| 品牌、型号、规格、卖点 | 用户确认资料；OCR 只提供候选 | 不生成未确认的数值和功效 |
| 单件 / 多件 / 多规格组合 | 用户输入或已确认商品清单 | 默认展示上传的主体；不猜售卖数量 |
| 材质 | 用户确认优先；图像只能推测视觉质感 | 用“呈现金属质感”等视觉描述，不当作实物事实 |
| 素材类型 | 自动区分白底图、透明图、实拍图、已有海报 | 已有海报不能直接当成干净商品图 |
| 用途与比例 | 默认商品创意样稿；允许用户切换 | 不把营销海报直接宣称为平台合规主图 |

自动化的原则是“少问，但不乱猜”。用户不填卖点时，可以用商品名称或不涉及性能的氛围短句完成首稿。

### 3.2 按五个维度选择方案

1. **商品是什么**：乳品、耳机、T 恤、椅子等具体子类。
2. **要表达什么**：外观质感、使用场景、已确认的卖点、真实组合。
3. **素材能支持什么**：是否完整、清晰；只有正面，还是有侧面/细节；是否已有模特图。
4. **品牌和商品的视觉特征**：颜色、材质、包装图形、风格偏好。
5. **输出用在哪里**：创意海报、详情模块、商品展示图；比例和信息量分别处理。

例如：同属“数码”，奶茶色耳机可以偏穿搭与日常，透明机身配件可以偏材质特写，办公设备可以偏桌面场景。路由到哪一条，取决于输入事实和素材，不由品类名直接决定。

## 4. 首版品类规则

下表是原创的待验证方案，不是对所引用品牌内部生产逻辑的描述。

| 品类 | 可规划的三种方向 | 重点设计变量 | 必须保留 | 限制与回退 |
| --- | --- | --- | --- | --- |
| 乳品 / 包装食品 | 日常食用场景、包装质感、图形化品牌表达 | 食用场景、包装色、台面关系、前后景、文字节奏 | 标签、瓶/盒型、口味、容量、商品数量 | 无内物实拍时不凭空展示剖面、配料或食物质地；本轮直接样本仅乳品 |
| 数码 / 小型电子产品 | 材质静物、适配的使用环境、外观图形海报 | 机身材质、硬软光、倾斜轴线、留白、标题形式 | 按键、接口、镜头、屏幕内容、Logo、准确比例 | 不编造内部结构、防水、续航等；单角度图不强造另一面 |
| 服装（首版平铺/挂拍） | 单品轮廓、搭配静物、编辑式海报 | 版型、面料可见细节、姿态、负空间、字号对比 | 领口、袖长、图案、纽扣、真实颜色与款式 | 不把平铺图简单贴到人体；没提供的颜色、搭配单品不伪装成在售款 |
| 家居（探索项） | 单品展示、生活空间、材质局部 | 房间透视、尺度、采光、构图、空间配色 | 腿/扶手结构、布纹、组件数、售卖范围 | 当前只看过扶手椅；尺寸未知不出精确空间比例/尺寸图 |

美妆、鞋包、珠宝、大型家电等目前没有足够的直接视觉观察，暂列后续样本扩展，不标为已验证支持。

### 4.1 金典：三套方案如何真正不同

已选择“清晨餐桌”为主要参考，可以保留另外两条方向做比较：

| 方案 | 表达目标 | 画面计划 | 字体与布局 | 素材边界 |
| --- | --- | --- | --- | --- |
| A 清晨餐桌 | 让人联想到早餐饮用时刻 | 暖木或亚麻台面、侧窗光、少量早餐道具；瓶子与台面接触自然 | 短标题放在上方安静区域；温和字形、有明确大小对比 | 这是一套原创场景设想；不借场景添加营养承诺 |
| B 包装质感 | 突出金盖、瓶身与包装配色 | 克制的紫/乳白环境、侧面塑形光、少量几何体 | 较凝练的标题，商品与文字不对称安排 | 保留真实标签和瓶型，不让模型重新“设计”包装 |
| C 图形表达 | 强化品牌辨识与视觉节奏 | 从包装已有色彩提取紫、绿、金；用抽象曲线或纸张层次 | 更鲜明的标题层级与图形节奏 | 花卉等装饰不能被写成商品原料；数值来自确认资料 |

三套都有独立的画面计划，不能只换一个背景色后套同一份排版。

### 4.2 耳机：同样的系统，不同的选择

- **材质静物**：沿用输入角度，围绕耳罩与头梁安排侧光和几何背景；标题简短，轮廓清楚。
- **生活桌面**：放入适配的书桌/旅行收纳场景，依据产品尺寸和原图光线匹配环境；不暗示额外配件随商品赠送。
- **图形海报**：使用产品颜色和圆弧轮廓建立节奏，以近景和大标题形成层级。

只有已有合适佩戴素材或经过验证的编辑路径时，才选择人物佩戴方案。不能仅凭“耳机”这个分类自动承诺可生成准确佩戴图。

### 4.3 T 恤：单品表现与真人上身分路处理

- **单品轮廓**：以原图的袖长、领口与褶皱为基础，调整背景、投影与留白。
- **搭配静物**：用经确认的配饰或辅助物组织画面；明确主售商品，不凭空制造套装关系。
- **编辑式海报**：在商品原图与已提供的局部细节图之间编排，运用标题和版面比例制造差异。

只有一张平铺图时，不能把模型生成的面料微距当成真实工艺细节。真人试衣需要独立的输入检查和效果验收。阿里云的[AI 试衣 API 文档](https://help.aliyun.com/zh/model-studio/outfitanyone-api)说明了服装图和人物图等输入要求；这是可研究的技术路径，不代表当前造物营已支持。

## 5. 每套方案必须输出什么

建议把模型输出从“背景提示词 + 左/右排版”升级为一份可检查的画面计划：

| 字段 | 内容 |
| --- | --- |
| concept | 方案名称、表达目标、为何适合该商品 |
| sourceFacts | 使用的事实及其来源；区分已确认与推测 |
| assets | 商品图、细节图、参考图的角色 |
| composition | 主体区域、标题区域、辅助信息区域；坐标随比例计算 |
| scene | 背景、允许的道具、商品落点和前后景关系 |
| lighting | 方向、软硬、色温，以及如何匹配商品原图 |
| palette | 背景、文字、强调色与选择依据 |
| typography | 可用字体、字重、字号关系、行数、字距、对齐方式 |
| productLocks | 不得改变的包装、结构、颜色、数量等 |
| renderRoute | 保留原商品合成 / 参考图编辑 / 专项流程 |
| fallback | 缺素材或能力不足时选哪种可完成的方案 |
| checks | 此方案最重要的商品与画面检查项 |

“三套差异”的首版验收建议：在场景、构图、光线、配色、排版五个维度中，每两套至少有三个维度存在有意义的区别。这是待校准的设计启发式，不是行业标准；用户明确要求统一风格时，以用户约束优先。

字体从实际可用且授权适配的字体库中选；一个方案同时控制字数、字重、行高和版面关系，避免简单替换字体名称。

## 6. 如何接到现有生成链路

这是后续开发建议，本次没有修改代码。

### 路线 A：保留商品，生成环境与版式

商品抠图与原始像素作为锁定层 → 每套生成不同环境 → 按计划合成商品 → 调整接触阴影和必要遮挡 → 用真实字体渲染文案。

适合包装准确性要求高、来源图片完整的商品。局限是原图的角度与光线必须和场景匹配；一张正面图无法支持任意镜头、复杂手持、倒液体或全新衣服姿态。

背景可以有道具、结构、光影和层次，但必须给商品和文字保留明确位置。不能用“禁止所有物体”来代替布局控制。

### 路线 B：参考图编辑，生成更完整的视觉样稿

商品图 + 可选风格参考 + 画面计划 → 支持参考图的编辑模型 → 检查结构/标签偏差 → 必要时恢复原商品或退回路线 A。

阿里云的[千问图像编辑文档](https://help.aliyun.com/zh/model-studio/qwen-image-edit-guide)公开了多图输入和编辑能力。它说明这种技术路线存在，不保证商品所有细节完全一致，也不等于当前选定的服务商、模型与接口已验证支持。

生成层中尽量不承担必须逐字准确的广告文案；文案后置为可编辑文字层。包装已有文字保留在原商品素材中，不依赖模型重写。

### 路线 C：专项能力

服装试衣、产品被手拿持、透明物体复杂透射等，按专项场景评估。缺少相应输入或能力时，自动切回静物/原图保留方案，并向用户说明当前完成的方式。

### 三处优先改动

1. **方案生成**：每个任务规划三份独立 concept，而非一个背景配两种固定布局。
2. **执行适配**：根据方案与供应商真实能力选路线；限制只放在该限制该部分，例如锁定商品而非禁止整个画面有内容。
3. **排版合成**：消费方案中的文字区域、字体、颜色和比例，保留可编辑状态。

模型生成成功与云端保存成功必须分开记录。保存失败应恢复已有结果；不能要求用户反复重新付费生成。此项是对产品链路的设计要求，本轮没有重新诊断线上故障。

## 7. 评审、badcase 和泛化验证

### 7.1 先过硬性检查，再评价美感

| 检查层 | 主要问题 | 处理 |
| --- | --- | --- |
| 商品保真 | 标签、外形、颜色、部件、数量错误 | 阻止直接定稿；恢复锁定素材或换路线 |
| 内容准确 | 凭空出现功效、数值、价格、赠品 | 移除无来源内容，重新排版 |
| 合成合理 | 悬浮、尺度异常、接触位置错误、光向冲突 | 修复相关层，不无条件整图重生 |
| 视觉表达 | 没有重点、道具抢主体、文字拥挤、三稿近似 | 修改构图/场景/排版计划 |
| 系统交付 | 成功结果未保存、历史无法恢复、下载失败 | 从已有输出恢复，记录交付故障 |

自动视觉检查只能辅助判断，尤其包装小字、服装纹理、精确硬件结构，需要原图对照与人工抽检。“生成完成”不等于“已可商用”。

badcase 至少记录：输入类型、类目、方案版本、模型/供应商、执行路线、原图与结果、失败阶段、现象标签、人工原因判断、修复动作、修复结果。将“背景不合适”与“商品被改写”“结果存不下来”分开。

### 7.2 一个可执行的小验证

建议使用未参与提炼规则的 18 个 SKU，乳品/数码/服装各 6 个；同类中覆盖不同外形、配色、单件/组合和难素材。每个 SKU 生成三稿，共 54 张，和旧流程在相同输入下比较。若两组都新生成，总计 108 张；这只是试验建议，本轮未发起生成或计费。

预留其中每类 2 个 SKU 作为留出样本，调整规则时不反复围绕它们修改。首版样本量很小，只用于找失败模式，不足以证明大规模商业提升。

关注四项：

- **首批三稿可选率**：至少有一稿被用户选中继续修改的任务 / 展示完整三稿的任务；同时报告任务失败率，避免只统计成功任务。
- **商品保真通过率**：通过商品核对的结果 / 完成评审的结果。
- **三稿有效差异率**：满足预先定义差异标准的三稿组 / 完成评审的三稿组。
- **得到首张可用素材的时间与返工次数**：同一评审口径下记录，而非只测接口速度。

上线后可观察采纳、编辑、导出等行为；真实投放效果需另行取得业务数据验证。

## 8. 后续补充淘宝样本的口径

当前状态为“待补充”，不是已经进行的研究。

若未来能够合规访问，或用户提供样本，建议先补核心三类，每类覆盖至少 5 家店铺、12—20 个不同 SKU，并同时记录日常/促销、品牌/中小商家、简洁/信息密集等差异。这是采样建议，不是统计代表性保证。
